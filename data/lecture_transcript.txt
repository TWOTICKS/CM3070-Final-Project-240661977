## Topic: Course Introduction and What Machine Learning Is
[00:00:05] Okay, good morning everyone, let's get started. Today's lecture is an introduction to machine learning, and I want to set up the vocabulary we'll be using for the rest of this module. So, what is machine learning? At a high level, machine learning is a set of techniques that allow a computer program to improve its performance on a task by learning from data, rather than being explicitly programmed with a fixed set of rules. Instead of a human writing down every rule for, say, recognising a cat in a photo, we show the system thousands of example photos labelled "cat" or "not cat", and the system gradually learns the patterns that distinguish them. The "learning" part usually means adjusting a large number of internal numerical parameters so that the model's predictions get closer to the correct answers over time. We'll see exactly how that adjustment happens later when we talk about gradient descent and backpropagation. For now, just remember the big idea: data in, patterns learned, predictions out.

## Topic: Supervised, Unsupervised, and Reinforcement Learning
[00:04:30] Now, machine learning is usually split into three broad categories. The first, and most common in industry, is supervised learning. In supervised learning, every training example comes with a label, or a "correct answer". Classic examples are spam detection, where emails are labelled spam or not spam, and house price prediction, where each house comes with its actual sale price. The model's job is to learn a mapping from inputs to these known outputs. The second category is unsupervised learning, where we don't have labels at all. Here the goal is to find structure in the data on its own, for example clustering customers into groups based on purchasing behaviour, without anyone telling the algorithm what the groups should be. The third category is reinforcement learning, which is a bit different again. In reinforcement learning, an agent interacts with an environment, takes actions, and receives rewards or penalties. Over time it learns a policy, a strategy for choosing actions, that maximises the total reward. Reinforcement learning is what underlies a lot of the game-playing AI you might have heard about, like systems that learn to play chess or video games purely from playing many, many games against themselves.

## Topic: Neural Network Fundamentals
[00:10:15] Let's move on to neural networks, since this is the foundation for almost everything else in this course. The simplest building block is called a perceptron, which is loosely inspired by a biological neuron. A perceptron takes several numerical inputs, multiplies each one by a weight, sums them up, adds a bias term, and then passes that sum through an activation function to produce an output. On its own, a single perceptron can only learn very simple, linearly separable patterns. The real power comes when we stack many of these units into layers, forming what we call a neural network. A typical network has an input layer, one or more hidden layers, and an output layer. Each connection between units has its own weight, and these weights are exactly the parameters that get learned during training. The activation function is important too - without it, stacking layers would just be equivalent to one big linear function. Common activation functions include the sigmoid function, which squashes values between zero and one, and the ReLU function, or rectified linear unit, which simply outputs zero for negative inputs and passes positive inputs through unchanged. ReLU is extremely popular in modern deep learning because it's computationally cheap and helps avoid some of the training problems that sigmoid can cause in deep networks.

## Topic: Training Neural Networks - Gradient Descent and Backpropagation
[00:18:40] So how does a network actually learn its weights? This is where gradient descent and backpropagation come in, and I'd say this is one of the most important things to understand in this entire module. First, we define a loss function, which is a single number that measures how wrong the network's predictions are compared to the true labels. For regression problems we might use mean squared error, and for classification we often use cross-entropy loss. The goal of training is to adjust all the weights in the network to make this loss as small as possible. Gradient descent does this by computing the gradient, that is, the derivative of the loss with respect to each weight, which tells us the direction in which the loss increases fastest. We then take a small step in the opposite direction, scaled by something called the learning rate. If the learning rate is too large, training can become unstable and the loss might bounce around or even increase; if it's too small, training can take an extremely long time. Backpropagation is the algorithm that efficiently computes all of these gradients for every weight in the network, layer by layer, starting from the output and working backwards towards the input, using the chain rule from calculus. Without backpropagation, training deep networks with millions of parameters simply wouldn't be computationally feasible.

## Topic: Overfitting, Underfitting, and Regularization
[00:27:50] Once you can train a network, the next big challenge is making sure it actually generalises to new data, rather than just memorising the training set. This brings us to overfitting and underfitting. Underfitting happens when a model is too simple to capture the underlying pattern in the data - it performs poorly on both the training data and new data. Overfitting is the opposite problem: the model becomes so complex, or is trained for so long, that it starts to memorise noise and specific quirks of the training examples, performing very well on training data but poorly on data it hasn't seen before. To detect this, we typically split our data into three sets: a training set used to fit the model, a validation set used to tune things like the learning rate and to monitor for overfitting during training, and a test set that is only used once, at the very end, to get an honest estimate of how the model will perform in the real world. To actually combat overfitting, we use regularization techniques. One popular method is dropout, where during training we randomly "switch off" a fraction of neurons in each forward pass, which prevents the network from relying too heavily on any single neuron and encourages more robust, distributed representations. Other common techniques include L1 and L2 weight regularization, which add a penalty term to the loss function based on the size of the weights, discouraging the model from becoming too complex, and early stopping, where we simply stop training once validation performance stops improving.

## Topic: Convolutional Neural Networks for Image Processing
[00:38:20] Let's now look at a specific architecture that has been hugely influential: the convolutional neural network, or CNN. CNNs are designed primarily for processing grid-like data such as images. Instead of connecting every input pixel to every neuron in the next layer, which would be computationally enormous and ignore the spatial structure of an image, a CNN uses small filters, sometimes called kernels, that slide across the image and compute local features. Early layers in a CNN tend to learn very simple features, like edges and corners, while deeper layers combine these into more complex shapes, and eventually into representations of entire objects like faces, cars, or in our earlier example, cats. Alongside convolutional layers, CNNs typically use pooling layers, which reduce the spatial size of the representation, for example by taking the maximum value in each small region, which helps make the network more efficient and somewhat more robust to small translations of the input. CNNs are the backbone of most modern image classification, object detection, and even some medical imaging diagnostic systems, because they dramatically reduce the number of parameters compared to a fully connected network while still capturing the spatial patterns that matter in visual data.

## Topic: Recurrent Neural Networks and Sequence Modelling
[00:46:55] Images aren't the only kind of data we care about - a lot of real-world data comes in sequences, like text, audio, or time series. For this kind of data, recurrent neural networks, or RNNs, were historically very popular. The key idea of an RNN is that it processes a sequence one element at a time, while maintaining a hidden state that acts as a kind of memory of everything it has seen so far. At each step, the network combines the current input with its previous hidden state to produce a new hidden state and, often, an output. This makes RNNs naturally suited to tasks like language modelling, where predicting the next word depends on the words that came before it. However, basic RNNs struggle with long sequences because gradients can either vanish or explode as they're propagated back through many time steps - this is often called the vanishing gradient problem. To address this, more sophisticated variants were developed, such as Long Short-Term Memory networks, or LSTMs, and Gated Recurrent Units, or GRUs, which use gating mechanisms to control what information is kept or discarded over time. More recently, transformer architectures, which use a mechanism called attention instead of recurrence, have largely overtaken RNNs for many sequence tasks, including the large language models that power tools like the AI assistant we're building in this course's project work.

## Topic: Evaluating Machine Learning Models
[00:55:30] Now let's talk about how we actually measure whether a model is any good. For classification problems, the simplest metric is accuracy, the proportion of predictions that are correct. But accuracy can be very misleading on imbalanced datasets - if ninety-nine percent of emails are not spam, a model that always predicts "not spam" gets ninety-nine percent accuracy while being completely useless. This is why we also look at precision and recall. Precision answers the question: of all the items the model predicted as positive, how many actually were positive? Recall answers: of all the items that were actually positive, how many did the model correctly identify? There's often a trade-off between the two, and a single metric called the F1 score, the harmonic mean of precision and recall, is commonly used to balance them. A confusion matrix is another really useful tool, it's a table that breaks down predictions into true positives, false positives, true negatives, and false negatives, giving you a much more complete picture than accuracy alone. For regression problems, common metrics include mean absolute error and mean squared error, which measure the average difference between predicted and actual values, with mean squared error penalising large errors more heavily because the differences are squared.

## Topic: Ethics and Bias in Machine Learning
[01:04:10] To finish today, I want to spend a few minutes on ethics, because this isn't an optional extra - it's central to being a responsible practitioner. Machine learning models learn from data, and if that data reflects existing societal biases, the model will learn, and often amplify, those biases. There have been well-documented cases of hiring algorithms that discriminated against women because they were trained on historical hiring data from male-dominated industries, and facial recognition systems that performed significantly worse on darker-skinned faces because the training data was not representative. Beyond bias, there are broader concerns around privacy, especially when models are trained on personal data, and around transparency - many modern deep learning models are effectively "black boxes", making it hard to explain why a particular decision was made, which matters a great deal in high-stakes domains like healthcare or criminal justice. Finally, as we build systems like the AI assistant for this project, which summarises lectures and answers questions automatically, we need to think about academic integrity and the risk of the system generating plausible-sounding but incorrect information, something often called hallucination in the context of large language models. We'll come back to some of these themes when we discuss evaluation of AI systems later in the course.
